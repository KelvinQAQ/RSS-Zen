# RSS-Zen v0.1.1

**Release commit:** `6a36c56`  
**Schema version:** 3  
**Upgrade source:** v0.1.0 / schema 3

## Highlights

- Replaced migration-time main-file copies with verified SQLite online-backup snapshots that
  include committed WAL data.
- Added date- and count-bounded backup retention, configured through `[backup]` and used
  consistently by CLI, `doctor`, and the systemd timer.
- Hardened the optional curl feed fetcher: HTTPS-only requests, manual revalidated redirects,
  response-size limits, private temporary files, and no request headers in process arguments.
- Added validated non-secret `headers` and environment-backed `header_env` for `Authorization`
  or `Cookie` feed credentials.
- Added bounded extract/translate batches, `--limit`, and `--dry-run`.
- Added BOM enforcement, dependency audit, Dependabot, and stricter production configuration
  file permissions.
- Removed the unsupported `deep-translator` Google Web provider because its dependency had an
  unresolved published vulnerability.

## Operator action required

- Replace `kind = "google"` provider configurations with a supported LibreTranslate,
  MyMemory, or OpenAI-compatible provider before upgrading.
- Add `[backup]` to production configuration if a backup directory or retention policy different
  from the defaults is required.
- Move feed `Authorization` and `Cookie` values from `headers` to `header_env` and the root-owned
  credential environment file.

## Upgrade and rollback

No database migration is introduced in this release. Upgrade normally with the locked release
procedure. Application rollback is safe while configuration continues to use supported provider
kinds and CLI options.
