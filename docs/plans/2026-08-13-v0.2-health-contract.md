# v0.2 Slice 3: Operational Health Contract

**Status:** In progress
**Target version:** v0.2.0
**Task:** local-only tracking `t-004`

## Goal

Provide stable, machine-readable `status --json` and `doctor --json` outputs for a single-host
RSS-Zen deployment. Health inspection must not contact feeds or providers and must never expose
credentials, headers, article bodies, private URL query values, or provider response content.

## Scope

### Stable JSON envelope

Both commands return additive JSON with:

```json
{
  "schema_version": 1,
  "generated_at": "2026-08-13T00:00:00+00:00",
  "healthy": true,
  "warnings": 0,
  "errors": 0
}
```

`schema_version` changes only for a breaking field rename/removal/type change. New optional fields
are additive within version 1.

### `status --json`

Add local repository and runtime facts:

- database path, schema version, main database bytes, WAL bytes, SHM bytes;
- disk free/total bytes for the database filesystem;
- feed totals, enabled totals, never-succeeded totals, and stale totals;
- processing counters already exposed by the command;
- batch totals (`running`, `interrupted`, `resumable_items`);
- configured backup directory, newest backup timestamp/path basename, age seconds, and directory
  byte total.

Staleness is deterministic and local: an enabled feed is stale when it has no successful sync or
when `now - last_success_at` is greater than twice its configured/effective poll interval.
Malformed stored timestamps are reported as stale, not parsed or logged verbatim.

### `doctor --json`

Keep the existing check list and add checks for:

- database sidecar/disk capacity;
- batch interruption/resumable work;
- configuration file owner/mode when metadata is readable;
- `curl` availability only when configured feeds use `fetcher = "curl"`.

Warnings do not change the exit code. Errors return exit code 1. Configuration/CLI parsing errors
retain their existing error handling. `doctor` does not initialize or migrate a database.

## Out of scope

- Prometheus, HTTP health endpoint, external alert delivery, or systemd timer.
- Provider network probes, cost estimation, or worker/queue metrics.
- Automatic remediation, service restart, or backup creation.

## Delivery order

1. Repository `health_snapshot` query and filesystem helper tests.
2. `status --json` schema v1 and deterministic staleness tests.
3. `doctor --json` checks and safe metadata tests.
4. Documentation and optional systemd health-check design (not enabled by default).

## Acceptance criteria

- JSON has `schema_version`, `generated_at`, `healthy`, warning/error counts.
- No health command makes external network calls or creates/migrates a database.
- WAL, disk, backup, feed, processing, and batch metrics are deterministic under tests.
- Stale feed calculation handles no success, overdue sync, and malformed timestamp safely.
- No output leaks secrets or article/provider content.
- Full quality gates pass.
