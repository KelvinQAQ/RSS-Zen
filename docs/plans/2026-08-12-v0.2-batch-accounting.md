# v0.2 Slice 1: Batch accounting and provider budgets

**Status:** Proposed for `feature/v0.2-batch-accounting`
**Target version:** v0.2.0
**Depends on:** v0.1.1 (`6a36c56`)

## Goal

Make explicit `translate` and `extract` commands stop predictably before exceeding an
operator-configured provider request or source-character budget, and emit a stable JSON report.
This slice does not change scheduled feed synchronization, create a database job queue, or add
checkpoint/resume persistence.

## Non-goals

- Predicting vendor token billing or monetary cost.
- Automatic extraction, asynchronous work, provider rate limits, or circuit breakers.
- Persisting batch state; that is Slice 2 (`--resume`).
- Changing the translation retry policy used by `serve`.

## Configuration

Extend `[limits]` with positive integer defaults:

```toml
max_provider_requests_per_run = 200
max_source_chars_per_run = 500000
```

Existing `max_extract_articles_per_run` and `max_translate_articles_per_run` remain the first
selection bound. A CLI `--max-requests` or `--max-source-chars` override may only lower the
configured limit unless `--unsafe-override-budget` is supplied explicitly. This prevents an
operator typo from silently increasing an approved provider budget.

## Accounting model

A new in-memory `RunBudget` owns:

- maximum and consumed provider requests;
- maximum and consumed source characters;
- skipped article IDs and the budget reason;
- `reserve(chars, requests)` before a provider request;
- immutable summary for human and JSON rendering.

Provider adapters receive a request observer/callback. They reserve **before each HTTP request**:

- LibreTranslate: one reservation per translated field request;
- MyMemory: one reservation per chunk request;
- OpenAI-compatible: one reservation per chunk request;
- AnySearch: one reservation per article extraction request;
- translating extracted full text uses the same translation observer.

The reservation uses the exact request text length after existing source field truncation/chunking.
A failed provider request still consumes its reservation because it reached the provider boundary.
Fallback providers consume additional requests only when actually called.

A budget denial is a non-retryable `AppError` with code `provider_budget_exhausted`. The command
stops before the denied provider request and reports remaining selected articles as skipped; it
does not write a fake failed translation/extraction record.

## Dry-run semantics

`--dry-run` remains network-free. It reports:

- selected article IDs and source characters;
- configured article/request/character ceilings;
- a lower-bound request estimate (`extract`: one per article; `translate`: one per non-empty
  source field before chunking/fallback);
- `estimate_only: true`.

It must never claim an exact request count because chunk splitting and provider fallback are only
known at execution time.

## Report contract

Add `--report-json PATH` to `translate` and `extract`; `-` writes JSON to stdout. The stable
versioned document is:

```json
{
  "schema_version": 1,
  "command": "translate",
  "dry_run": false,
  "selected_articles": 12,
  "completed_articles": 10,
  "failed_articles": 1,
  "skipped_articles": 1,
  "source_chars": 48211,
  "provider_requests": 37,
  "limits": {"articles": 50, "source_chars": 500000, "provider_requests": 200},
  "skipped": [{"article_id": 42, "reason": "provider_budget_exhausted"}]
}
```

`--report-json` is additive: existing line-oriented CLI output and exit status remain compatible.
The report file is written atomically after processing. A budget-exhausted run exits 1 because
selected work was not completed; `--dry-run` exits 0 when selection is valid.

## Test plan

1. Model tests reject zero/negative budgets and retain backward-compatible defaults.
2. Unit tests reserve exact chunks, reject the first over-budget request, and count failed requests.
3. Provider adapter tests prove fallback requests are counted and denied before network I/O.
4. Extraction tests prove AnySearch calls consume one request and translated extracted text shares
   the translation budget.
5. CLI tests cover dry-run report, atomic JSON report, budget-exhausted output, and existing
   unreported output compatibility.
6. No tests contact external providers.

## Delivery order

1. Add failing `RunBudget` unit tests and configuration tests.
2. Add request-observer injection to provider/extractor interfaces without changing default behavior.
3. Wire budget into explicit CLI commands only.
4. Add report rendering and documentation.
5. Run lint, test suite, dependency audit, BOM check, and a CLI smoke test.

## Exit criteria

- No provider request is issued after its budget would be exceeded.
- Exact runtime request and source-character totals appear in execution reports.
- Dry-run performs no provider/network calls and labels estimates correctly.
- Existing `serve` behavior and persisted retry semantics are unchanged.
- Full project quality gates pass.
